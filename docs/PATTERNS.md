# Patterns: how to add a feature

Only patterns with working code behind them are described here. Always copy the closest existing example instead
of inventing a new pattern; the first feature built end to end (basic login) is listed under "Worked example".
The running example is a made-up `widgets` resource in a module `<module>` (e.g. `marketplace`).

## Where a module's code lives
The code is organised **by layer**, with **one file per module inside each layer**:

| Layer | Backend file | Frontend file |
|---|---|---|
| Model (tables) | `backend/app/models/<module>.py` | |
| Schema (request/response shapes) | `backend/app/schemas/<module>.py` | |
| Service (business logic, DB access) | `backend/app/services/<module>_service.py` | |
| Route (HTTP endpoints) | `backend/app/routes/<module>.py` | |
| Tests | `backend/tests/test_<module>_*.py` | `*.test.jsx` next to the file |
| API hooks | | `frontend/src/api/<module>.js` (camelCase, e.g. `caWorkspace.js`) |
| Pages | | `frontend/src/pages/<role>/<Name>Page.jsx` |
| Seed data | a function in `backend/app/seed.py` | |
| Scheduled job | a line in `backend/worker.py` | |

Registration is explicit (no auto-discovery): a blueprint goes into `BLUEPRINTS` (`backend/app/routes/__init__.py`),
a model into `backend/app/models/__init__.py`, a seed function into `SEEDS`, a page into `frontend/src/routes.jsx`.
Shared code (listed in `CLAUDE.md`) is used by every module; call out changes to it in the PR.

## Foundations

### Layering
| Layer | Does | Never |
|---|---|---|
| Route (`routes/`) | parse input (`@blp.arguments`), call **one** service function, serialize (`@blp.response`) | query, touch `db.session`, hold business rules |
| Service (`services/`) | business logic and all DB access; each public function is one unit of work | query another module's models |
| Model (`models/`) | columns, relationships, constraints (data only) | logic, queries, commits |

A module that needs another module's data calls that module's **service functions** (listed in its module doc).

### Transactions
- Each public service function validates, changes rows and calls `db.session.commit()` **once, at its end**. For
  an expected problem it raises `ApiError` before committing; Flask-SQLAlchemy rolls back at the end of the request.
- Helpers that other service functions compose do **not** commit; their docstrings say "Does not commit."
- One exception: a state change that must survive the error it causes (a wrong one-time code counts as an attempt)
  is committed right before the `ApiError` is raised (`_use_code()` in `backend/app/services/auth_service.py`).
- `flask seed` follows the same rule: seed functions don't commit, `run_all_seeds()` commits once.
- Tests: services really commit; the `database` fixture (`backend/tests/conftest.py`) deletes every row after
  each test.

### Base model and enums
- Every model subclasses `BaseModel` (`backend/app/models/base.py`): UUID `id` plus `created_at`/`updated_at`
  (timezone-aware UTC). User-facing rows add `SoftDeleteMixin` first: `class Document(SoftDeleteMixin, BaseModel)`
  gives `is_active` and `deleted_at`; services soft-delete, nothing is hard-deleted.
- Enums (`backend/app/models/enums.py`) are `StrEnum`s with lowercase snake_case values, stored as text with a
  CHECK constraint via `str_enum()`:
  ```python
  class WidgetStatus(StrEnum):
      DRAFT = "draft"
      IN_REVIEW = "in_review"

  status: Mapped[WidgetStatus] = mapped_column(str_enum(WidgetStatus))
  ```
  The API sends the code; the frontend shows a label from `frontend/src/lib/labels.js`; codes and labels are listed
  in `docs/DATA_MODEL.md`. Adding a value later needs a hand-written migration that replaces the CHECK constraint.
- Constraint and index names come from the naming convention in `backend/app/extensions.py`, so migrations are
  identical on every machine.

### Errors and logging
- `raise ApiError(409, "DUPLICATE_WIDGET", "A widget with this name exists.")` (`backend/app/errors.py`) or
  `abort(404)`. Every error body is `{"error": {"code", "message", "details?"}}`; never build error JSON by hand.
- `log = logging.getLogger(__name__)` at the top of a file, then `log.info("...")`. No `print` outside `main.py`.
  Never log PII (PAN, GSTIN, names, emails, phones, document contents); log IDs instead.

## Worked example: basic login
- **Table + migration + seed:** `User(SoftDeleteMixin, BaseModel)` in `backend/app/models/user.py` (imported in
  `models/__init__.py`); migration `backend/migrations/versions/2026_09_25_1912-80850e135434_core_auth_create_users_table.py`
  (autogenerated by `make migration`, reviewed, unchanged); `seed_demo_users()` in `backend/app/seed.py`
  (idempotent, no commit), tested in `backend/tests/test_seed_command.py`.
- **Service:** `authenticate()` in `backend/app/services/auth_service.py` (raises `ApiError`, commits once).
  Simpler: `get_dashboard(user)` in `backend/app/services/compliance_service.py`.
- **Route + schema + role check:** `backend/app/routes/compliance.py` with `backend/app/schemas/compliance.py`;
  a public endpoint with a request body, rate limit and documented errors: `Login` in `backend/app/routes/auth.py`.
- **Tests:** `backend/tests/test_compliance_dashboard.py` (allowed role, other roles 403, no token 401) and
  `backend/tests/test_auth_login.py`.
- **Frontend:** page `frontend/src/pages/business/BusinessDashboardPage.jsx` with the hook
  `useComplianceDashboard()` (`frontend/src/api/compliance.js`); form `frontend/src/pages/LoginPage.jsx` (React Hook
  Form + Zod, one message per API error code); tests `LoginPage.test.jsx` and `context/AuthProvider.test.jsx`.

## 1. Backend route
One flask-smorest Blueprint per module, **without** a `url_prefix` (it is registered under `/api/v1`). Every route
spells out its module segment, so URLs are easy to grep:

```python
# backend/app/routes/<module>.py
from flask.views import MethodView
from flask_smorest import Blueprint

from app.models.enums import UserRole
from app.schemas.<module> import WidgetCreateSchema, WidgetSchema
from app.services import <module>_service
from app.utils.decorators import current_user, roles_required

blp = Blueprint("<module>", __name__, description="...")

@blp.route("/<module>/widgets")
class Widgets(MethodView):
    @roles_required(UserRole.BUSINESS)          # first: 401/403 before anything else runs
    @blp.response(200, WidgetSchema(many=True))
    def get(self):
        return <module>_service.list_widgets(current_user())

    @roles_required(UserRole.BUSINESS)
    @blp.arguments(WidgetCreateSchema)          # request body validated -> 422 on errors
    @blp.response(201, WidgetSchema)
    def post(self, data):
        return <module>_service.create_widget(current_user(), **data)
```
Then add `<module>.blp` to `BLUEPRINTS`. Protect **every** endpoint with `@roles_required(...)` (or
`@login_required` for any role); a public endpoint declares `@blp.doc(security=[])` instead. After changing a route
or schema, update the frontend calls of that endpoint.

## 2. Schemas
`schemas/<module>.py` holds request and response shapes (marshmallow). Name them uniquely across modules
(`ComplianceDashboardSchema`, not `DashboardSchema`): the OpenAPI name comes from the class name. Money:
`fields.Decimal(as_string=True, places=2)`; timestamps: `fields.DateTime()` (UTC); dates: `fields.Date()`.

## 3. Model + migration
```python
# backend/app/models/<module>.py
class Widget(SoftDeleteMixin, BaseModel):     # id (UUID), created_at, updated_at, is_active, deleted_at
    __tablename__ = "widgets"
    name: Mapped[str] = mapped_column(String(200))
    price: Mapped[Decimal] = mapped_column(Numeric(12, 2))  # rupees
    status: Mapped[WidgetStatus] = mapped_column(str_enum(WidgetStatus))
```
Import it in `backend/app/models/__init__.py` (or Alembic will not see it). Then: pull main →
`make migration name="<module>: add widgets"` → review the generated file → `make migrate`. One migration per PR.
Add the table to `docs/DATA_MODEL.md` and the module doc.

## 4. Seed data
A `seed_<module>()` function in `backend/app/seed.py`, listed in `SEEDS` after what it depends on (demo users
first). Idempotent (check before insert), no commit. Run with `make seed`.

## 5. Scheduled job
```python
# backend/worker.py, in build_scheduler()
scheduler.add_job(<module>_service.send_widget_digest, "cron", hour=8, id="<module>.widget_digest")
```
Jobs run only in the worker process (`make dev-worker`), inside the Flask app context. Cron times are IST. The job
function is a service function (one unit of work, commits once).

## 6. Tests
- Backend: `backend/tests/test_<module>_*.py` with the fixtures in `backend/tests/conftest.py`: `app`, `client`,
  `database` (request it in any test that touches the DB), `make_user(role=UserRole.CA)` and
  `auth_headers(user)` for `client.get(url, headers=auth_headers(user))`.
- Frontend: `*.test.jsx` next to the code, Vitest + React Testing Library. Fake the backend with
  `fakeApi({"GET /api/v1/...": [200, body]})`, log in with `loginAs(role)` and render with `renderApp(path)`
  (`frontend/src/test/utils.jsx`). Example: `frontend/src/routes.test.jsx`.

## 7. Frontend page, route and nav link
```jsx
// frontend/src/routes.jsx
export const NAV = {
  business: [
    // ...
    { label: "Widgets", path: "/business/widgets" }, // sidebar link, in display order
  ],
};

roleArea("business", [
  // ...
  { path: "widgets", element: <WidgetsPage /> }, // -> /business/widgets
]),
```
Areas: public (`/`), business (`/business`), CA (`/ca`), admin (`/admin`); each role's prefix is `ROLE_HOME` in
`frontend/src/lib/session.js`. `roleArea()` wraps each area in `RequireRole`, so pages need no guard of their own.
A page that is not built yet renders `<Placeholder>` (example: `pages/business/DocumentsPage.jsx`).

## 8. Frontend data fetching
```js
// frontend/src/api/<module>.js
import { useQuery } from "@tanstack/react-query";

import { apiFetch } from "@/api/client";

export function useWidgets() {
  return useQuery({
    queryKey: ["<module>", "widgets"],
    queryFn: () => apiFetch("/api/v1/<module>/widgets"),
  });
}
```
`apiFetch(path, { method, body })` adds the token, returns the parsed JSON, and throws `ApiRequestError`
(`status`, `code`, `message`). Show a failure with `errorMessage(query.error)`; switch on `error.code` when a page
reacts to a specific error (example: `LOGIN_ERROR_TEXT` in `pages/LoginPage.jsx`). Field names are the API's
snake_case names (Swagger at `/api/docs`). Forms: React Hook Form + Zod. A component used by several pages goes in
`components/`; one used by a single page stays in that page's file.

## 9. Sending an email
Write the body as plain text in `backend/app/templates/email/<template>.txt` (Jinja: `{{ name }}`), then call
`send_email()` from a service, **after** `db.session.commit()`:

```python
from app.utils.email import send_email

send_email(user.email, "Your CA Helper verification code", "verify_email", name=user.full_name, code=code)
```
In development the mail lands in Mailpit (http://localhost:8025). A failure is logged and returns False; it never
raises. In tests nothing is sent: read the messages from the `mailbox` fixture (`backend/tests/conftest.py`).
Example: `_email_code()` in `backend/app/services/auth_service.py`, tested in `backend/tests/test_auth_signup.py`.

## Checklist for a new feature
- [ ] route (thin, in `BLUEPRINTS`) + schema + service (commits once) + tests
- [ ] `@roles_required(...)` on every endpoint (or `@blp.doc(security=[])` if it is public on purpose)
- [ ] model on `BaseModel` (+ `SoftDeleteMixin`, `str_enum()`), imported in `models/__init__.py`, one migration,
      seed data
- [ ] frontend page + route + nav link + API hook + test
- [ ] module doc updated (what exists now, tables, endpoints, services, contracts)
